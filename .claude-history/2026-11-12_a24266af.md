## Claude（2026-11-12 12:48）

「打ち消し」は、効果の動きの一つ `Action.counter` として作られています。「フィールド上」でないゾーン（スタック）にあるカードを、解決させずに墓地へ送る動きです。

## 中身

**1. 中間表現**（`CardGen/IR.lean:200`）
```lean
| counter (target : Selector)
```
破壊やバウンスと同じように、範囲（`Selector`）を一つ持つだけの動きです。

**2. モデル**（`CardGen/Model.lean:151`）
```lean
def PState.counter (r : Rules) (sel : Selector) (q : PlayerId) (src : Src) (s : PState) : PState :=
  let hit := fun sl : Slot => !r.onFieldZone sl.zone && sel.matches (sl.view r q src)
  { s with field := s.field.filter (fun sl => !hit sl),
           grave := s.grave ++ (s.field.filter hit).map (·.card) }
```
中身は `PState.destroy` とほぼ同じで、違うのは条件の `onFieldZone` が逆になっている点だけです。破壊は「フィールド上」のカードを墓地へ送り、打ち消しは「フィールド上」でないカードを墓地へ送ります。モデルでは、スタックのカードも `field`（マスに置かれたカードの一覧）に入っていて、そのゾーンが「フィールド上」に数えられないだけです。`State.applyAction` では、両方のプレイヤーに `s.counter` をかけています（`Model.lean:281`）。

**3. 対象と解決**
- 対象を一つ選ぶ効果（`target …`）なので、解決するときに範囲に合うカードを1枚選びます（`.resolve … (some (p, i))`）。
- 打ち消されたカードは盤面から消えるので、その効果が解決されることはありません。打ち消し専用の「解決しない」状態は持っていません。

**4. 見本と検査**
- 見本の対抗呪文は `CardGen/Mtg.lean:115` にあります：`.activated [.counter (target [instant, sorcery] .opp)]`
- `Mtg.lean:338` のテストでは、相手のスタックの紅蓮地獄が解決されずに墓地へ行き、対抗呪文も墓地へ行くことを確かめています。
- 形式の検査（`IR.lean:342`）は、打ち消す範囲の種類が「フィールド上」でないゾーンに置けるかを調べ、置けなければ警告を出します。その場合の根拠が `State.counter_eq_self`（`Warnings.lean:166`）で、到達できる盤面ではその打ち消しが何もしないことを示しています。
- `Flow.lean:90` の `pflow_counter` は、打ち消してもカードの枚数が保たれる（移動先が墓地なだけ）ことを示しています。

## 「無効」とは別のものです
`CardGen/Negation.lean` にあるのは「効果を無効にする」関係の判定（どのカードが有効かを決める安定な状態と、メタ定理1）で、打ち消しとは別です。無効になったカードは盤面に残り、効果だけが働かなくなります（モデルでは `negS`・`neg` の一覧として引数で受け取ります）。

## Claude（2026-11-12 15:35）

これは、カードが持てる効果の種類を決めている定義です（`CardGen/IR.lean:215`）。

## 読み方

`inductive` は「この中のどれか1つ」という型を作ります。効果は次の5種類のどれかで、1枚のカードはこれを並べたもの（`effects : List Effect`）を持ちます。それぞれの後ろの括弧は、その効果が持つ中身です。

| 種類 | 意味 | 中身 | 例 |
|---|---|---|---|
| `activated` | 発動する効果。解決すると、動きを順に行う | 動きの並び（破壊・手札に戻す・ドロー・ダメージ・回復・打ち消し など） | 魔法カード、MTG のインスタント（対抗呪文は `.activated [.counter …]`） |
| `negate` | 永続効果。表側表示でフィールド上にある間、範囲に合うカードの効果を無効にする | 範囲 | 「〜の効果は無効になる」というカード |
| `boost` | 永続効果。範囲に合うカードの攻撃力を変える | 範囲と増える量（負なら下げる） | 「攻撃力を500上げる」装備魔法、MTG の賛美歌 |
| `toughen` | 永続効果。`boost` の守備力版 | 範囲と量 | |
| `triggered` | 誘発する効果。条件を満たしたら動きを行う | 条件・「〜できる」かどうか・動きの並び | 召喚成功時・破壊されたとき・ターンの始めに〜 |

- **範囲**（`Selector`）は、効果が及ぶカードの条件です。種類・タグ・どちらの側か・表側表示だけか・自分を除くか・マスの近さ・対象を1つ選ぶか、を指定します。
- **誘発の条件**（`Trigger`）は次の3つです：`placed`（表側表示で置かれたとき）・`destroyed`（フィールド上から破壊されて墓地へ送られたとき）・`turnStart`（持ち主のターンの始め）。
- `optional` が `true` なら「〜できる」で、持ち主は行わないことも選べます。`false` なら必ず行います。

最後の `deriving …` は、表示（`Repr`）・等しいかの判定（`DecidableEq`）・JSON との読み書き（`FromJson`/`ToJson`）を自動で作る指定です。`CardGen/mtg.json` のようなカードの JSON が読めるのは、このおかげです。

## 大きく2つに分かれる

- **動く効果**（`activated`・`triggered`）は、一度だけ盤面を変えます。中身の動きは `State.applyAction` が行います（前の質問の打ち消しもここに入ります）。
- **永続効果**（`negate`・`boost`・`toughen`）は盤面を変えません。置かれている間ずっと、値の計算に効きます。
  - `boost`/`toughen` は、攻撃力・守備力を計算するとき（`State.atkOf`・`defOf`）に足されます。
  - `negate` は、どのカードがどれを無効にするかという関係になり（`Negation.lean:263`）、そこから安定な状態として「どれが無効か」が決まります。無効にされたカードは、自分の永続効果も、発動・誘発した動きも働きません。

永続効果の範囲では対象を選べません。`IR.lean:355` の `noTarget` で、形式の検査として弾いています。

## Claude（2026-11-12 15:35）

貼ってもらった定義を例に、出てくる構文を上から順に説明します。

## 1. ドキュメントコメント `/-- … -/`

```lean
/-- カードの効果 -/
inductive Effect
```

`/--` で始まり `-/` で終わるのは、すぐ下にあるものの説明です。エディタでは、名前にカーソルを当てると表示されます。ほかに次の2つがあります。

- `/-! … -/`：ファイルや節の見出しになる説明（`Negation.lean` の冒頭など）
- `--`：行末までのふつうのコメント

## 2. `inductive`：場合分けで型を作る

```lean
inductive Effect
  | activated (actions : List Action)
  | negate (target : Selector)
  ...
```

「`Effect` という型の値は、`|` で並べた形のどれか1つ」という宣言です。`|` の後ろの名前（`activated` など）は**コンストラクタ**（値の作り方）です。他の言語で近いものは次のとおりです。

- Rust の `enum Effect { Activated(Vec<Action>), Negate(Selector), … }`
- C# なら、抽象クラス `Effect` と、そのサブクラス5つ

## 3. コンストラクタの引数 `(名前 : 型)`

```lean
| boost (target : Selector) (amount : Int)
```

`boost` は `Selector` と `Int` を1つずつ持つ、という意味です。`名前 : 型` は「この名前の値はこの型」と読みます。Lean では型を常に `:` の後ろに書きます。

- `List Action`：`Action` のリスト。型の引数は、括弧なしで空白区切りで並べます（C# の `List<Action>`）
- `Int`：整数（負もある）。`Nat` は 0 以上の整数です
- `Bool`：`true` / `false`

## 4. 値の作り方

コンストラクタは関数のように、引数を空白で区切って呼びます。

```lean
Effect.boost sel 500           -- 正式な名前
.boost sel 500                 -- 型が分かっている場所では Effect を省略できる
.activated [.counter (target [instant, sorcery] .opp)]
```

- `[a, b]` はリストです
- 関数呼び出しに括弧やカンマは使いません。`f x y` は `f(x, y)` と同じです。括弧は、引数そのものが式のときにまとめるためだけに使います（`(target … .opp)`）
- 先頭の `.`（`.opp` など）は、「期待される型の名前空間から探す」という省略です

## 5. 値の使い方：`match` で場合分け

`Model.lean` にある例です。

```lean
def Effect.atkMod : Effect → Option (Selector × Int)
  | .boost s n => some (s, n)
  | _ => none
```

- `def 名前 : 型` で関数を定義します。`Effect → Option (…)` は「`Effect` を受け取って `Option (…)` を返す」という意味です
- 下の `| 形 => 結果` で、どのコンストラクタだったかに応じて結果を書きます。`.boost s n` の形に合えば、その中身が `s`・`n` という名前で取り出せます
- `_` は「それ以外ぜんぶ」です
- `Option α` は「`some 値` か `none`」です（C# の null 許容型に近い）。`A × B` は組（タプル）で、`(s, n)` と書きます
- Lean は、場合分けに漏れがあるとエラーにします。そのため、効果の種類を足すと、それを扱う場所がすべてコンパイルエラーで見つかります

`match` 式として書くこともできます。

```lean
match e with
| .negate s => some s
| _ => none
```

## 6. `deriving`：決まった機能を自動で作る

```lean
deriving Repr, DecidableEq, FromJson, ToJson
```

| 名前 | 作られるもの |
|---|---|
| `Repr` | `#eval` などで値を表示する方法 |
| `DecidableEq` | `a == b` や `if a = b then …` で等しいかを判定する方法 |
| `FromJson` / `ToJson` | JSON との読み書き（`mtg.json` を読むのに使う） |

中身を手で書かなくても、型の形から機械的に作られます。C# でいえば、`record` が `Equals` や `ToString` を自動で持つのに近いです。

## 7. ほかのファイルでよく見る構文

| 構文 | 意味 |
|---|---|
| `structure S where  a : A  b : B` | フィールドに名前のある組（C# の class/record）。`Selector` がこれ。`near : Near := .any` の `:=` は既定値 |
| `{ s with life := 0 }` | `s` の `life` だけ変えた新しい値（C# の `with` 式と同じ） |
| `fun x => …` | 無名関数（C# の `x => …`） |
| `let x := …` | 局所的な変数 |
| `namespace CardGen … end` | 名前空間 |
| `def PState.counter …` | `PState` の名前空間に関数を置く。こうすると `s.counter r sel q src` とメソッドのように呼べる |
| `theorem 名前 : 命題 := by …` | 定理。`:` の後ろが主張で、`by` の後ろが証明（タクティク） |
| `#guard 式` | ビルド時に式が `true` か確かめる（テスト） |

## 8. 型と証明の関係（このリポジトリならでは）

`Bool` は計算結果としての真偽で、`Prop` は証明する対象の命題です。たとえば `Negation.lean` には次の定義があります。

```lean
def wrong (f : Nat → Bool) (x : Nat) : Bool := …        -- 計算できる判定
def Stable (f : Nat → Bool) : Prop := ∀ x < S.n, S.wrong f x = false   -- 命題
```

`∀ x < S.n, …` は「`S.n` より小さいすべての `x` について …」という意味です。この形の命題を `theorem` で証明したものが、`spec/check.sh` で照合される「証明済み」の定理になります。

negateの効果はどうやって無効の関係になるの？

## Claude（2026-11-12 16:02）

`CardGen/Negation.lean` の後半（「カードから作る関係」の節）で、3段階で作られています。

## 1. 効果から範囲を取り出す（`Effect.negSel`）

```lean
def Effect.negSel : Effect → Option Selector
  | .negate s => some s
  | _ => none
```

`negate` の効果ならその範囲（`Selector`）を返し、ほかの効果なら `none` を返します。

## 2. 盤面のカードを「実体」として並べる（`Inst`）

```lean
structure Inst where
  card : Card
  controller : PlayerId
  faceUp : Bool
  cell : Option Cell := none
```

同じカードが2枚あっても、別の実体として扱います。範囲の判定には、陣営・表裏・マスの位置が要るからです。

## 3. 実体どうしの関係を作る（`instRel`）

```lean
def instRel (insts : List Inst) (y x : Nat) : Bool :=
  match insts[y]?, insts[x]? with
  | some a, some b => a.faceUp && a.card.effects.any fun e => match e.negSel with
      | some s => s.matches (b.viewFrom a (y == x))
      | none => false
  | _, _ => false
```

`y` 番目の実体 `a` が `x` 番目の実体 `b` を無効にするのは、次の2つを両方満たすときです。

- `a` が表側表示である
- `a` の効果のどれかが `negate s` で、`b` が範囲 `s` に合う

「範囲に合うか」は、`a` から見た `b` の姿（`viewFrom`）で決めます。中身は、種類・タグ・`a` の味方か・表側か・`a` 自身か（`y == x`）・隣か・同じ列か、です。そのため、「相手の」「自分以外の」「隣の」といった条件が、見る側によって正しく変わります。

最後に `System.ofInsts insts := ⟨insts.length, instRel insts⟩` で、前半のメタ定理1が扱う `System`（`n` 枚と関係 `rel y x`）になります。

## 4. この関係から「どれが無効か」が決まる

関係があるだけでは、どのカードが無効かはまだ決まりません。無効にされたカードの `negate` は働かないので、連鎖が起きるからです（A が B を無効にし、B が C を無効にするなら、C は有効）。そこで前半の「安定な状態」が使われます。

- 有効なカードは、どの有効なカードにも無効にされていない
- 無効なカードは、ある有効なカードに無効にされている

この関係に循環がなければ、安定な状態はちょうど1つに決まり、判定の手続きは必ず止まります（`System.settles`）。

## 5. カードの一覧だけで確かめる（`negation_settles`）

盤面は無数にあるので、カードの段階で確かめます。

- `mayNegate c d`：カード `c` のどれかの実体が、`d` のどれかの実体を無効にしうるか。陣営・表裏・位置は見ず、種類とタグだけで、多めに見積もります。
- `rankOK cards rank`：`mayNegate c d` なら、`c` の順位が `d` より小さいか。
- `negation_settles`：`rankOK` が通れば、そのカードだけが並ぶ**どの盤面でも**メタ定理1が成り立ちます。

`instRel` が真ならいつも `mayNegate` も真である、ということを `mayNegate_of_instRel` で示しています。これが、カードの段階の確認と盤面の関係をつないでいます。

検査ツールでは `checkNegation` を使います。順位を自動で計算し（`computeRanks`：自分を無効にしうるカードからの最長の道の長さ）、結果は次の3つのどれかです。

- `proved`：循環がない
- `cyclic`：循環がある。循環しているカードのまとまりも報告する（`negCycles`）
- `none`：`negate` を持つカードがない

## 注意：対戦のモデルとは、まだつながっていません

`Model.lean` の対戦のモデルは、`instRel` からどれが無効かを計算していません。無効なカードの一覧（`neg`・`negS`）を動きの引数として受け取り、**どんな組み合わせも許します**（`Model.lean:16` のコメント）。今はこうなっています。

- 対戦のモデルで証明した性質は、無効の組み合わせがどうであっても成り立ちます。本当の安定な状態はその組み合わせの一つなので、本当の対戦でも成り立ちます。
- 無効の判定そのものの性質（止まる・1通りに決まる）は、`Negation.lean` で別に証明しています。
- 循環がある場合の振る舞い（安定な状態が複数ある・一つもない、など）は、`Explore.lean`・`Timed.lean` で、盤面ごとに総当たりで調べています。

## 共通して足りない土台

複数のゲームで要るものを抜き出すと、次の6つです。

1. **カードの重なり**：進化・エネルギー・進化元。今の `Slot` は1マスに1枚の実体だけを持ちます。
2. **カードを資源にする**：マナゾーン・ピッチ。今は、マナを出すのは決まったカード（土地）をタップすることだけです。
3. **ほかの勝ち方**：シールド・サイド・セキュリティ。今は、ライフと、デッキから引けないことだけです。
4. **効果の動きの種類**：デッキから探す・手札を捨てる・ゾーンからゾーンへ動かす・カードを選ぶ。冒頭のコメントにあるとおり、「盤面の制約を守る動きだけに絞る」方針で、今は8種類しかありません。
5. **戦闘とターンの形の選択肢**：攻撃できるゾーンを決める・ワザ・攻撃でターンが終わる・手札で守る・ダメージが残る。今は遊戯王式と MTG 式の2通りだけです。
6. **共有の資源とターンの移り方**：デジモンのメモリー。

## 足すときの注意（このリポジトリ特有）

仕組みを足すと、`Model.lean`・`Turn.lean` の `Step`・`Match.step?` などの定義が変わります。凍結した主張（`spec/Spec/Statements.lean`）は、これらの定義を使っています。そのため、

- 文面が同じでも主張の意味が変わる。変えた内容を、返答とコミットメッセージに書く決まりです。
- 今通っている証明（カードの枚数が保たれる・無効の判定が止まる など）は、新しい動きごとに証明し直しが要ります。重なり（1マスに複数枚）は、カードの枚数を数える部分の証明に広く効きます。

これまでも、版 2〜9 でこの形のまま少しずつ足してきたので、同じやり方で広げることはできます。ただし、どれか一つのゲームを丸ごと入れるには、上の土台の 1〜3 が先に要ります。

どれかを目標にするなら、デュエマが一番近いです。マナとタップ・ブロック・クリーチャー戦は MTG の分がほぼそのまま使えて、新しく要るのはシールド・マナゾーン・S・トリガー・進化の4つです。どのゲームに寄せたいか、または特定の仕組み（例えば重なり）から入れたいかがあれば、設計の案を作ります。
