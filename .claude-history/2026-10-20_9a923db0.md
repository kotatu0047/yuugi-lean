これは「**闇属性のモンスターの枚数は、モンスター全体の枚数を超えない**」という当たり前のことを、Lean に一歩ずつ納得させている証明です。これはジョブ 0001（`jobs/done/0001/Job.lean`）の補題です。

## 何を言っているか（定理の文）

```lean
countWhere rules claim.matches s ≤ fieldCount rules (some "モンスター") s
```

- 左辺 `countWhere ... claim.matches s`：フィールド上の「闇属性のモンスター」の枚数
- 右辺 `fieldCount ... "モンスター" s`：フィールド上の「モンスター」の枚数

つまり **闇属性モンスターの数 ≤ モンスターの数** です。

## なぜ必要か

メインの証明 `job_proof` の流れはこうです。

1. ルールから「モンスターは最大5枚」が言える（すでに証明済みの★）
2. この補題で「闇属性モンスターの数 ≤ モンスターの数」
3. 1 と 2 を合わせて「闇属性モンスターは最大5枚」

## 証明の各行

どちらの数も「フィールドのカード一覧から、条件に合うものを残して（filter）数える」という形をしています。

| 行 | やっていること |
|---|---|
| `unfold countWhere fieldCount` | 2つの関数の中身を展開する。「条件Aで絞った一覧の長さ ≤ 条件Bで絞った一覧の長さ」という形が見えるようになる |
| `apply length_filter_le_of_imp` | 汎用の補題を使う。中身は「**Aを満たすものは必ずBも満たす**なら、Aで絞った一覧はBで絞った一覧より長くならない」。これで、残る仕事は「Aを満たすカードは必ずBも満たす」を示すことだけになる |
| `intro sl _ h` | カードを1枚（`sl`）取り、「そのカードは条件Aを満たす」という仮定を `h` と名付ける |
| `simp only [Bool.and_eq_true] at h ⊢` | 「X かつ Y」という条件を、X と Y の2つに分ける。A は「フィールドのゾーンにある **かつ** 闇属性モンスター」、B は「フィールドのゾーンにある **かつ** モンスター」 |
| `refine ⟨h.1, ?_⟩` | 前半の「フィールドのゾーンにある」は A でも B でも同じなので、仮定をそのまま使う。残るのは後半だけ |
| `have hm := h.2` / `simp only [claim, ...] at hm` | 仮定の後半「闇属性モンスターである」を、`claim` の定義（種類が「モンスター」かつタグに「闇属性」）まで展開する |
| `simp only [Option.all_some, beq_iff_eq]` | 示したいこと「種類が `some "モンスター"` に合う」を、単純な等式「"モンスター" = カードの種類」に直す |
| `exact (... hm.1 ...).symm` | `hm.1`（種類はモンスター）から「カードの種類 = "モンスター"」を取り出し、`.symm` で左右を入れ替えてゴールに合わせる |

## まとめ

要するに「闇属性モンスターを数えるときの条件は、モンスターを数えるときの条件より厳しい（属性の条件が1つ増えている）。だから数は増えない」というだけの話です。行数が多いのは、Lean が `&&` や `Option.all` のような定義をそのままでは理解しないので、ひとつずつ普通の論理の形にほどいているからです。

c.tags.all card.tags.contains　これ解説して欲しい

## Claude（2026-10-20 13:42）

これは「**命題で指定したタグを、カードがすべて持っているか**」を調べる式です。`CustomClaim.matches`（`CardGen/Custom.lean`）の後半にあたります。

## 部品ごとの意味

| 部品 | 意味 | 例（ジョブ 0001） |
|---|---|---|
| `c.tags` | 命題で指定したタグの一覧 | `["闇属性"]` |
| `card.tags` | カードが持っているタグの一覧 | サイコ・ショッカーなら `["闇属性", "機械族"]` |
| `card.tags.contains` | 「タグを1つ受け取って、カードがそれを持っていれば true を返す関数」 | `card.tags.contains "闇属性"` → true |
| `l.all f` | 一覧 `l` の**すべての**要素で `f` が true なら true | |

`card.tags.contains` は、本来 `card.tags.contains t` のようにタグ `t` を渡して使う関数です。ここではあえて `t` を書かずに、関数のまま `all` に渡しています。省略せずに書くと次のようになります。

```lean
c.tags.all (fun t => card.tags.contains t)
```

普通の言葉にすると「命題のタグ `t` のどれについても、カードのタグに `t` が含まれている」です。集合でいえば **c.tags ⊆ card.tags** です。

## 具体例

命題のタグが `["闇属性"]` のとき：
- サイコ・ショッカー `["闇属性", "機械族"]` → `"闇属性"` を持っているので **true**
- サンダー・ボルト `[]` → 持っていないので **false**

命題のタグが `["闇属性", "戦士族"]` のとき：
- Bloo－D `["闇属性", "戦士族"]` → 両方持っているので **true**
- サイコ・ショッカー → `"戦士族"` がないので **false**

命題のタグが `[]`（指定なし）のとき：
- どのカードでも **true** になります。一覧が空なら「すべての要素で〜」は無条件に成り立つ、というのが `all` の決まりです。だから「タグの指定なし＝タグで絞らない」になります。

## 種類（types）の条件との違い

同じ式の前半 `c.types.isEmpty || c.types.contains card.type` とは、組み合わせ方が違います。

- **種類**：指定した種類の**どれか1つ**に当てはまればよい（「または」）。カードの種類は1つしかないからです。
- **タグ**：指定したタグを**すべて**持っている必要がある（「かつ」）。

つまり「種類が モンスター、タグが 闇属性・戦士族」なら、「モンスターであって、闇属性**かつ**戦士族のカード」という意味になります。
