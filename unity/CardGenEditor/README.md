# CardGen Editor（Unity・実行時のアプリ）

ノードをつないでカードゲームのルールとカードを作り、その場で形式を検査し、Lean の検査ツールで★と無効の関係を検査するエディタ。

## 開き方

Unity は WSL のファイルシステム上のプロジェクトを開けない（大文字小文字を区別するため）。
Windows 側のクローン（例：`C:\Users\yamam\repo\yuugi-lean`）の `unity/CardGenEditor` を Unity Hub で開く（Unity 6000.6.6f1）。

- メニュー「CardGen ＞ プロジェクトを準備」：PanelSettings とシーン（`Assets/CardGenEditor/Main.unity`）がなければ作る
  （シーンを作り直したいときは、ファイルを消してから実行する）
- メニュー「CardGen ＞ Windows 用にビルド」：`Build/CardGenEditor.exe` を作る

C# の中核（中間表現・形式の検査・盤面の計算）は `csharp/CardGen.Core` をローカルのパッケージとして使う。

### WSL で編集して、Windows 側でビルドする

Windows 側のクローンは「ビルド用の写し」として扱い、編集は WSL 側で行う。WSL から次のスクリプトで写してビルドする。

```
tools/unity-build.sh                         # 作業中のファイルを Windows 側に写し、バッチモードでビルドする
tools/unity-build.sh --reset                 # 先に Windows 側のクローンの変更を捨てて git pull する
tools/unity-build.sh --shot 画面.png -cardgen-play 7   # ビルドしたアプリを動かし、画面を保存する
```

```
tools/unity-build.sh --test                  # エディタと画面の自動テスト（Unity Test Framework・EditMode）を動かす
```

Windows 側のクローンの場所は `CARDGEN_WIN_REPO`、Unity.exe は `CARDGEN_UNITY` で変えられる
（既定は Windows のユーザーフォルダの `repo/yuugi-lean` と、`ProjectVersion.txt` の版の Unity Hub のエディタ）。

## 使い方

見た目は SF 映画の画面のような HUD 風（ほぼ黒の紺の地、シアンの細い線、四隅のブラケット、方眼のキャンバス、光るつなぎ線、うっすらとした走査線）。
形式の問題があるノードは、上に流れる警告テープ（アンバーと黒の斜めの縞）、赤い太枠、見出しの「!! FAULT」の札、下に問題の文が出て、赤い光彩が速く明滅する（破壊のノードの赤と区別できるように）。
選んでいるノードはアンバーの光彩と四隅がゆっくり明滅し、つなぎ線の上を親から子へ光の点が流れる。
Lean で検査している間は、流れ続けるプログレスバーと経過時間、ログ（送った中間表現の大きさ・コマンド・受け取った報告・★の件数）を出し、
終わったあとも結果の下に「検査のログ」として残す（ログは実際に起きたことだけで、進み具合の見せかけの数字は出さない）。
配色と飾りは `Runtime/Theme.cs`、ボタン・入力欄・スクロールバーは `Resources/CardGenTheme.tss` にまとめてある。

| つなぐ | 右の丸から別のノードの左の丸へドラッグ（ルール→ゾーン、カード→発動・無効、発動→破壊・手札に戻す・ドロー、破壊・手札に戻す・無効→範囲） |

## テストプレイ

上の「テストプレイ」で、作ったルールとカードを両プレイヤー分1人で動かせる（デッキはカードの一覧を繰り返して混ぜたもの）。

- ドロー・手札を置く・魔法を発動する・攻撃する。動きは C# の対戦エンジン（Lean の `State.step?` と差分テスト済み）で進める
- ライフ（ルールの初期ライフが 0 でなければ）と勝敗、戦闘できるカードの攻撃力・守備力（無効にされていない攻撃力の変化を足したもの）を表示する
- **ターン：** C# の `Match`（Lean の `CardGen/Turn.lean` と差分テスト済み）で進める。「ターン終了」で相手のターンになり、
  新しいターンプレイヤーがルールの枚数を引く。カードを置く・攻撃するのはターンプレイヤーだけで、場のカードの発動はどちらの
  ターンでもできる。戦闘できるカードを置けるのは1ターンにルールの回数まで、攻撃は1ターンに1枚1回まで、先攻の最初のターンは
  ルールで許したときだけ攻撃できる。「相手の先攻で最初から」で先攻を入れ替えられる。ターンのルールはルールのノードで決める
- **マナとタップ：** マナを出すカードを選んで「タップしてマナを出す」。手札のカードはコストの分のマナがあれば置ける。
  マナは色ごとの数で表示し（例：赤2・緑1）、色の決まったコストはその色で、残りは無色のマナから先に自動で払う。
  タップしているカードは薄く表示し、マナはターンの終わりに消える。召喚酔いのカードには「召喚酔い」と出る
- **ブロック（MTG 式の戦闘）：** 攻撃するカードを何枚でも宣言すると、右側に「ブロック」の欄が出て、攻撃されたプレイヤーが
  ブロックできるカードごとに「ブロックしない」か「攻撃 n を止める」を選ぶ（1枚の攻撃を何枚で止めてもよい）。
  選んだ割り当てでの結果（破壊されるカード・残るダメージ・プレイヤーへのダメージ）を C# の対戦エンジンで計算して予告し、
  「このブロックで戦闘する」で戦闘のダメージを与える
- **ダメージ：** 戦闘できるカードには、攻撃力・守備力（変化があれば元の値も）と、受けているダメージを表示する。ダメージはターンの終わりに消える
- **インスタントとスタック：** ターンプレイヤーでない方も、手札のインスタントを選んで置ける（その前に、自分のマナを出すカードを
  選んでタップする）。スタックのルールでは、右側の「スタック」の欄に積まれた呪文が上から並び、一番上だけを解決できる
- **払うマナ：** 手札を選ぶと、払うマナ（自動の払い方）が出る。「＋赤」などで自分で選び直せる。2色から選べる土地は、
  タップするときに色ごとのボタンが出る
- **勝敗：** ライフが 0 になるか、ターンの最初に引けなければ（デッキ切れ）、対戦が終わる
- **優先権：** 右側の「優先権」の欄に、優先権を持つプレイヤーと「パスする」ボタンが出る。動けるのは優先権を持つプレイヤーだけで、
  相手に応答させたいときはパスする。両者が続けてパスすると、スタックの一番上を解決するか、ブロックを選べるようになる
- **対象：** 対象を選ぶ範囲の動きを持つカードを発動すると、右側に「対象を選ぶ」の欄が出て、選べるカードのボタンが並ぶ
- **状態の確認：** 動きのたびに、守備力以上のダメージを受けている（守備力が 0 の）クリーチャーを自動で破壊し、記録に残す
- **飛行：** 飛行を持つ攻撃には、飛行か到達を持つカードでしかブロックを割り当てられない
- **無効の状態：** フィールドのカードごとに、効果が「有効・無効」かを表示する。カードが適用された順番を覚えておき、
  盤面が変わるたびに OCG の手順（Lean の `CardGen/Timed.lean` の `TSys.succ`。C# では `Judge`）で判定を進める。
  互いに無効にし合う2枚は先に適用された方が勝ち（相手の Bloo－D がいるところに出した自分の Bloo－D は無効）、
  同時に適用を始めるカードはターンプレイヤーのものが先になる。どう選んでも結果が1通りならそこまで自動で進め、
  プレイヤーが選ぶ場面（同じプレイヤーのカードを複数、有効に戻せるときなど）だけ選択肢を出す。判定が止まらない盤面ではそう表示する
- **マス目：** マスの位置があるゾーンは、盤面のマス目の並び（上が相手、下が自分）で表示する。手札を選ぶと、置ける空きのマスに
  「ここに置く」が出る（右の欄で表側・裏側を切り替える）。「隣」「同じ縦列」の効果はこの並びで決まる
- 盤面の制約（枚数・置けるゾーン・1マス1枚）が成り立っているかを毎回表示する（Lean で証明済みなので、崩れたら C# 側の誤り）

- **右クリックのメニュー：**
  - 手札のカード：右の欄と同じ動き（置く・置く向き）と、詳細（種類・コスト・マナ・攻守・能力・効果）
  - 場のカード：右の欄と同じ動き（発動・タップ・攻撃など）と、今の攻守・ダメージ・召喚酔いの詳細。対象を選んでいる途中なら
    「このカードを対象にする」、ブロックを選ぶ場面なら「攻撃 n を止める／ブロックしない」と「このブロックで戦闘する」、
    スタックの一番上なら解決
  - 空きのマス：そこに置ける手札（同じカードは1つ。置く向きも切り替えられる）
  - プレイヤーの盤面：ライフ・デッキ・手札・墓地の枚数とマナ、パス・ターン終了、手札を選ぶ、墓地の中身（新しい順）
  - 盤面や右の欄の空き場所：今できる動き、パス・両者がパスする・ターン終了・自動で今のターンを進める・選択を解除、
    最初から・先攻を替えて最初から、動作確認の場面（MTG 風の見本のとき）、記録をコピー、エディタに戻る

## Lean による検査

「Lean で検査」は、右の欄のコマンドで検査ツールを動かす。既定は WSL の中のビルド済みの検査ツール：

```
wsl.exe --cd ~ -e repo/yuugi-lean/.lake/build/bin/cardgen -
```

（WSL のホームの `repo/yuugi-lean` にあるリポジトリの検査ツール。WSL 側で `lake build` しておく。
別の場所に置いたときは欄を書き換えるか、環境変数 `CARDGEN_COMMAND` にコマンドを入れる。欄の値は次回も使われる。
アプリは Lean のコンパイラを動かさず、ビルド済みの検査ツールを呼ぶだけ）

## 命題とジョブ

右下の「命題とジョブ」で「フィールド上の、条件に合うカードは最大 n 枚」という命題を追加できる。
検査ツールが実際に対戦を進めて反例を探し、なければ証明のジョブ（`jobs/pending/`）にする。
ジョブは開発中は Claude が証明する（`jobs/README.md`）。「ジョブの状態を更新」で一覧を表示する。

## 自動テスト（`Assets/CardGenEditor/Tests/EditMode`）

Unity Test Framework の EditMode のテストで、画面の部品を作り、ボタンを文字で探して押して（`UiTest.Press`）、
C# の対戦エンジンの状態と記録で結果を確かめる。ボタンは `UiTest.Btn` で作り、押したときの処理を覚えておく
（パネルに載っていない要素にはクリックのイベントが届かないため）。

- どの種類のノードも、表示とインスペクタを作れる（見本の全ノードと、新しく加えたノード）
- つなぎ先の候補を選ぶと、つないだ状態で親の右に加わる（「打ち消す」の候補は範囲だけ）
- 「整列」で親が子の左に来て、中間表現は変わらない
- 集合の値の名前を変えると、カードとルールの種類も変わる。値と、タグの集合を加えられる
- 命題の欄の種類とタグは、集合から選ぶ
- MTG 風のテストプレイ：最初の手札の土地に「置ける」と出て、置いてタップでき、2枚目の土地は置けない
- 戦闘の場面：熊2体のブロックで丘巨人が破壊され、ブロックされなかった攻撃は相手に届く
- スタックの場面：両者がパスするまで解決できず、パスしたら一番上（稲妻）から解決する
- 対象の場面：ショックで選んだカードだけが破壊される
- デモで8ターン進めても、盤面の制約が成り立ち、できない動きは出ない
- 右クリックのメニュー：ノードのメニューでつなぐ・つなぎを外す・削除ができ、集合は削除できない。空き場所のメニューで、
  クリックした位置にノードを加える。カードのメニューの動きは右の欄のボタンと同じ。空き場所のメニューでパスしてスタックを解決できる
- テストプレイのメニュー：空きのマスのメニューで手札をそのマスに置ける（同じカードは1つ）。場のカードのメニューでブロックを
  割り当てて戦闘でき、対象を選べる。プレイヤーのメニューに手札と山札の枚数、空き場所のメニューの「両者がパスする」と場面（MTG 風だけ）

`tools/unity-build.sh --test` で動かし、結果（成功・失敗とその理由）を表示する。失敗があれば終了コード 2。

## 動作確認用のコマンドライン

```
CardGenEditor.exe -cardgen-select 6 -cardgen-check -cardgen-results-end -cardgen-screenshot C:\path\shot.png
```

見本を読み込み、6番のノードを選び、Lean で検査し、結果を一番下まで送って、画面を保存して終了する。
`-cardgen-mtg` を付けると、最初に MTG 風の見本を読み込む。
`-cardgen-play 14` を付けると、テストプレイを始めて、14ターンの間、ターンごとに置ける手札を1枚置いてターンを終える。
`-cardgen-arrange` で並べ直し、`-cardgen-candidates Activate` で発動のノードの候補の一覧を出す（画面の確認用）。
`-cardgen-scenario combat`（または `stack`・`target`）を `-cardgen-mtg -cardgen-play 0` と一緒に付けると、MTG 風の見本で、
まとめての攻撃とブロックの割り当ての場面（またはスタックで応答した場面）を作る。
`-cardgen-menu node`（または `play`・`card`・`field`・`cell`・`player`）で、発動のノード（テストプレイの空き場所・自分の最初の手札）の右クリックのメニューを出す。
`-cardgen-open <パス>` で最初にそのファイルを開く。`-cardgen-focus` は種類の名前（`Card` など）でもよい。
`-cardgen-check-live` で検査を始めて終わるのを待たない（検査中の表示の確認用）。
`-cardgen-claim` を付けると、命題の欄の値でジョブを作る（実際にジョブが増えるので注意）。
