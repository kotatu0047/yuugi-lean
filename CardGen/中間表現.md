# 中間表現（版 9）

ビジュアルエディタが出力し、Lean の検査ツールと C# のゲームエンジンが共有する JSON 形式。
定義は `CardGen/IR.lean`、見本は `CardGen/sample.json`（`CardGen/Sample.lean` と同じ内容であることをビルドで確認）。

## 前提（全ユーザー共通、中間表現には書かない）

- プレイヤーは自分と相手の2人
- 相手のフィールドは自分のフィールドを逆さまにした形。ゾーンは1人分だけ書く
- 優先権：優先権を持つプレイヤーだけが動ける。動いた本人が持ち続け、パスすると相手に移る。両者が続けてパスしたら、
  スタックの一番上を解決するか、攻撃の途中ならブロックに進み、どちらでもなければ何も起きない。どのあともターンプレイヤーに戻る
  （下の「ターン」）
- 盤面全体（2人分）のマス目は最大 50×50。ここでは中心のマスがあるように 49×49 とする（`gridSize`）。
  遊戯王は、その中央の一部だけを使う

## 全体

| フィールド | 型 | 意味 |
|---|---|---|
| `version` | 数 | 形式の版。今は `9`（版 2 でライフと戦闘、版 3 でターンのルール、版 4 でマスの位置、版 5 でマナとタップ、版 6 で色のマナ、版 7 でタグの集合、版 8 でインスタント・スタック・カードへのダメージ・守備力の変化・選べるマナの色・トランプル、版 9 で対象を選ぶ範囲・ターンの終わりまでの変化・打ち消し・飛行と到達を加えた） |
| `rules` | Rules | ゲームのルール |
| `cards` | Card の配列 | カードの定義 |

`Option` でないフィールドはすべて必須（省略すると読み込みエラー）。

## Rules

| フィールド | 型 | 意味 |
|---|---|---|
| `cardTypes` | 文字列の配列 | カードの種類（例：モンスター、魔法、罠） |
| `deckSize` | 数 | 1人あたりのデッキの枚数 |
| `handSize` | 数 | 初期手札の枚数 |
| `zones` | Zone の配列 | ゾーンの定義（1人分） |
| `life` | 数 | 初期ライフ |
| `fighters` | 文字列の配列 | 戦闘できる（攻撃する・攻撃される）カードの種類。空なら戦闘はない |
| `summonsPerTurn` | 数 | 1ターンに置ける、戦闘できる種類のカードの枚数（通常召喚の回数）。0 なら制限なし |
| `drawPerTurn` | 数 | ターンの最初に引く枚数 |
| `firstTurnDraw` | 真偽 | 先攻の最初のターンにも引くか |
| `firstTurnAttack` | 真偽 | 先攻の最初のターンにも攻撃できるか |
| `placeLimits` | `{"types": [種類…], "count": n}` の配列 | 1ターンに置ける枚数の上限（種類ごと。例：土地は1ターンに1枚） |
| `attackTaps` | 真偽 | 攻撃するとタップする（タップしているカードは攻撃できない） |
| `summoningSickness` | 真偽 | 置いたターンには、戦闘できるカードで攻撃したりマナを出したりできない（召喚酔い） |
| `blocking` | 真偽 | MTG 式の戦闘（攻撃されたプレイヤーがブロックするカードを選ぶ。下の「戦闘」） |
| `manaColors` | 文字列の配列 | マナの色（例：白・青・黒・赤・緑）。空なら色のマナは使わない |
| `tagSets` | `{"name": 名前, "values": [値…]}` の配列 | タグの集合（例：属性＝闇属性・光属性）。1つでもあれば、カードと範囲の指定のタグはどれかの集合の値でなければならない |
| `instants` | 文字列の配列 | いつでも置ける種類（インスタント）。相手のターンや、攻撃・スタックへの応答としても置ける（下の「ターン」） |
| `stack` | 真偽 | スタック：「フィールド上」でないゾーンに置いた、発動する効果を持つカード（呪文）は、後に置いたものから解決する |

Unity のエディタは、古い版のファイルを開くと今の版に上げる。版 2 はターンのルールを既定の値（1・1・引かない・攻撃できない）にし、
版 2・3 はゾーンのマスの位置を空（マス目の上にない）、範囲の指定のマスの関係を `"any"` にする。
版 2〜4 は、マナとタップを使わない値（`placeLimits` は空、`attackTaps`・`summoningSickness`・`blocking` は偽、カードの `cost`・`mana` は 0）にする。版 2〜6 は、タグの集合を空（タグは自由）にする。版 2〜5 は、色のマナを使わない値（`manaColors`・`colorCost` は空、`manaColor` は `""`）にする。
版 2〜7 は、インスタントなし（`instants` は空）・スタックなし・選べるマナの色なし（`manaChoice` は空）・トランプルなしにする。
版 2〜8 は、範囲の指定の `target` を偽（範囲に合うものすべて）、カードの `flying`・`reach` を偽にする。

## マスの並び（Cell）

マスの並びは、縦と横の2本の序列で表す。マスは `{"col": 列, "row": 行}` で、列・行は 0 以上 49 未満。
使うのは大小の比較と「1つ隣」だけで、距離や角度は使わない。

- ゾーンの `cells` は自分（`true` のプレイヤー）の側だけ書く。相手のマスは、中心のマス（24, 24）について点対称の位置
  （列 → 48 − 列、行 → 48 − 行）。そのため、自分の左端のマスの向かいに相手の右端のマスがくる
- 隣のマス：列か行のどちらかが同じで、もう一方が1つ違う（上下左右）
- 同じ縦列：列が同じ（相手の側のマスも含む）
- 1枚まで（`"one"`）のゾーンでは、1つのマスに置けるカードは1枚。カードを置くときはマスを選ぶ

見本（遊戯王）は、モンスターカードゾーンを行 25、魔法罠ゾーンを行 26 の列 22〜26 に置く。相手の側は行 23・22 になり、
行 24（中心の行）は空く。

```
列 →        22   23   24   25   26
行 22  相手の魔法罠ゾーン（4 3 2 1 0 番目のマス）
行 23  相手のモンスターカードゾーン（4 3 2 1 0）
行 24  （空き）
行 25  自分のモンスターカードゾーン（0 1 2 3 4）
行 26  自分の魔法罠ゾーン（0 1 2 3 4）
```

## Zone

| フィールド | 型 | 意味 |
|---|---|---|
| `name` | 文字列 | ゾーンの名前 |
| `count` | 数 | 1人あたりのマスの数 |
| `capacity` | `"one"` / `"many"` | 1マスに1枚まで／何枚でも |
| `role` | `"deck"` / `"grave"` / `"plain"` | デッキ・墓地として手順が使うゾーンか |
| `onField` | 真偽 | 「フィールド上」に数えるか |
| `admits` | 文字列の配列 | 置けるカードの種類 |
| `cells` | Cell の配列 | マスの位置（自分の側。`count` 個）。空ならマス目の上にないゾーン |

## Card と効果

| フィールド | 型 | 意味 |
|---|---|---|
| `name` | 文字列 | カード名（重複不可） |
| `type` | 文字列 | カードの種類 |
| `tags` | 文字列の配列 | 属性・種族など |
| `effects` | Effect の配列 | 効果 |
| `attack` | 数 | 攻撃力（戦闘できる種類のカードが使う） |
| `defense` | 数 | 守備力（裏側表示で攻撃されたときに使う） |
| `cost` | 数 | 置くのに支払うマナのうち、どの色でも払える分 |
| `colorCost` | 文字列の配列 | 置くのに支払うマナのうち、色の決まった分（例：`["白", "白"]`。色は `manaColors` のどれか） |
| `mana` | 数 | タップすると出るマナの量（土地など） |
| `manaColor` | 文字列 | タップすると出るマナの色（`""` なら無色） |
| `manaChoice` | 文字列の配列 | タップするときに選べるマナの色（2色以上の土地。空でなければ `manaColor` は `""` にする） |
| `flying` | 真偽 | 飛行（MTG 式の戦闘で、飛行か到達を持つカードでしかブロックできない） |
| `reach` | 真偽 | 到達（飛行を持つカードもブロックできる） |
| `trample` | 真偽 | トランプル（MTG 式の戦闘でブロックされたとき、ブロックしたカードを破壊できるだけのダメージを与え、残りを相手に与える） |

Effect は次のどれか。

- `{"activated": {"actions": [Action, …]}}`：発動し、解決したときに動きを順に行う。
  あとの動きは、前の動きの結果の盤面に行う（例：守備力を上げてから 3 点なら残り、3 点が先なら破壊される）。
  対象を選ぶ動きが複数あれば、どれも解決する前に選んだ同じ1枚に行い、それが先の動きでなくなっていれば何もしない。
  対象を選ばずに解決すると、対象を選ぶ動きだけが何も起きない（見本：「破壊と補給」「電解」「稲妻のらせん」）
- `{"negate": {"target": Selector}}`：表側表示でフィールド上に存在する限り、範囲に合うカードの効果を無効にする
- `{"boost": {"target": Selector, "amount": n}}`：表側表示でフィールド上に存在し、効果が無効にされていない限り、
  範囲に合うカードの攻撃力を n 変える（n は負でもよい。攻撃力は 0 未満にならない）
- `{"toughen": {"target": Selector, "amount": n}}`：同じように、範囲に合うカードの守備力を n 変える（`State.defOf`）

Action は次の6種類。どれもカードを移すか、ライフやカードの受けたダメージを変えるだけなので、盤面の制約（★）を崩さないことを
証明済み（`CardGen/Inv.lean`）。

- `{"destroy": {"target": Selector}}`：範囲に合うカードをすべて破壊し、持ち主の墓地へ送る
- `{"bounce": {"target": Selector}}`：範囲に合うカードをすべて持ち主の手札に戻す
- `{"draw": {"count": n}}`：発動したプレイヤーがデッキからカードを n 枚引く（足りなければある分だけ。n は1以上）
- `{"damage": {"amount": n}}`：相手に n のダメージを与える（ライフは 0 より下がらない）
- `{"heal": {"amount": n}}`：発動したプレイヤーのライフを n 回復する
- `{"strike": {"target": Selector, "amount": n}}`：範囲に合う、戦闘できるカードすべてに n のダメージを与える（n は1以上）。
  ダメージはカードに残り、守備力以上のダメージを受けた戦闘できるカードは破壊される
- `{"pump": {"target": Selector, "attack": a, "defense": d}}`：範囲に合う、戦闘できるカードすべての攻撃力を a、守備力を d、
  ターンの終わりまで変える（例：巨大化 ＋3/＋3）。守備力が受けているダメージ以下になった（MTG 式の戦闘では 0 になった）カードは破壊される
- `{"counter": {"target": Selector}}`：範囲に合う、「フィールド上」でないゾーンのカード（スタックにある呪文など）を、
  解決させずに墓地へ送る（打ち消す）。範囲の種類は「フィールド上」でないゾーンに置ける種類にする

## 戦闘

表側表示の戦闘できるカードは、相手のフィールド上の戦闘できるカードを攻撃できる（相手にいなければ直接攻撃）。
攻撃力は、元の攻撃力に、無効にされていない `boost` を足したもの（`State.atkOf`）。守備力も同じように `toughen` を足したもの（`State.defOf`）。

- 表側表示のカードどうし：攻撃力の低い方を破壊し、差をそのコントローラーへのダメージにする。同じなら両方を破壊する（ともに 0 なら何も起きない）
- 裏側表示のカード：守備力で受ける。攻撃力が高ければ破壊し（ダメージなし）、低ければ差を攻撃した側へのダメージにする。裏側のまま残る
- 直接攻撃：攻撃力をそのまま相手へのダメージにする

**MTG 式の戦闘**（`blocking`、`State.combat`）では、攻撃するプレイヤーが攻撃するカードを宣言し（何枚でもよい）、
攻撃されたプレイヤーが、攻撃ごとにブロックする戦闘できるカードを割り当てる（1枚の攻撃を何枚でブロックしてもよい。
ブロックするカードは、このターンにまだブロックしておらず、`attackTaps` ならタップしていないもの）。ダメージは同時に与える。

- ブロックされなかった攻撃：攻撃力をそのまま相手へのダメージにする（相手に戦闘できるカードがいても）
- ブロックされた攻撃：攻撃力のダメージを、ブロックしたカードに割り当てた順に割り振る（前のカードには、破壊できるだけ
  ＝守備力から受けているダメージを引いた分を与えてから次へ。最後のカードには残りすべて。`trample` のカードは、
  最後のカードにも破壊できるだけ与え、残りを相手に与える）。ブロックしたカードは、
  それぞれの攻撃力のダメージを攻撃したカードに与える。プレイヤーへのダメージはない。表側・裏側は関係しない

**状態の確認**：守備力以上のダメージを受けている戦闘できるカードと、MTG 式の戦闘では守備力が 0 の戦闘できるカードは、
ダメージを受けたとき・ターンの終わりまでの変化を受けたとき・状態の確認（どちらのプレイヤーもいつでもできる動き `settle`。
テストプレイは動きのたびに自動で行う）で破壊される。

**ダメージは残る**：カードが受けたダメージはカードに記録され（`Slot.damage`）、ダメージを受けたあと、守備力以上の（0 でない）
ダメージを受けている戦闘できるカードを破壊する（`State.sweep`）。ターンのある対戦では、ターンの終わりにどのカードのダメージも消える。
守備力を下げる効果や、守備力を上げる効果が無効になったことで、すでに受けているダメージが守備力以上になっても、
次の状態の確認までは破壊されない。
MTG 風の見本は `CardGen/Mtg.lean`（`CardGen/mtg.json`）。

## ターン（`CardGen/Turn.lean`）

対戦のモデルは2段になっている。

- **ターンのないモデル**（`Step`・`Reachable`）：どちらのプレイヤーもいつでも何度でも、置く・発動する・攻撃する・引くことができる。
  ★と盤面の制約は、このモデルのすべての盤面について証明する
- **ターンのあるモデル**（`Match.step?`・`TReachable`）：その上にターンを重ねたもの
  - **優先権（公理）**：優先権を持つプレイヤーだけが動ける（最初とターンの始めはターンプレイヤー）。動いた本人が
    優先権を持ち続け、パス（`pass`）すると相手に移る。両者が続けてパスしたら、スタックがあれば一番上を解決し、
    攻撃の途中ならブロックを選び、どちらでもなければ何も起きない。どのあとも優先権はターンプレイヤーに戻る。
    スタックの一番上の解決とブロックは、両者がパスしたときだけできる。状態の確認は優先権によらずいつでもできる
    （`Match.step?_prio`）
  - カードを置く・攻撃するのはターンプレイヤーだけ。場のカードの発動はどちらのプレイヤーもできる（優先権を持つとき）
  - 戦闘できる種類のカードを置くのは、1ターンに `summonsPerTurn` 枚まで
  - 攻撃は1ターンに1枚1回まで。先攻の最初のターンは `firstTurnAttack` のときだけ攻撃できる
  - 「ターン終了」で相手のターンになり、新しいターンプレイヤーが `drawPerTurn` 枚引く（デッキが足りなければある分だけ）。
    先攻の最初のターンは `firstTurnDraw` のときだけ引く。それ以外に引くのは効果によるときだけ
  - マナ：ターンプレイヤーは、表側表示の「フィールド上」の、マナを出すカード（`mana` が 1 以上）をタップして、
    その色（`manaColor`）のマナを得る。カードを置くときは、どのマナで払うかを選ぶ。払うマナは持っているマナの一部で、
    `colorCost` の色をすべて含み、全部で `cost` ＋ `colorCost` の数だけ（`payOK`）。マナはターンの終わりに消える。
    テストプレイは、色の決まった分をその色で、残りを無色のマナから先に払う（`autoPay`）
  - タップしたカードは、持ち主の次のターンの始めに起きる。`attackTaps` なら攻撃でもタップし、タップしているカードは攻撃できない
  - `placeLimits` の種類のカードは、1ターンにその枚数までしか置けない
  - `summoningSickness` なら、置いたターンの戦闘できるカードは攻撃もタップもできない
  - `blocking` なら、ターンプレイヤーは攻撃するカードを1枚ずつ宣言し（何枚でもよい）、攻撃されたプレイヤーがブロックを
    まとめて選ぶと戦闘のダメージを与える。宣言からブロックまでの間は、インスタント以外は置けず、ターン終了もできない
  - インスタント（`instants` の種類）は、いつでも置ける。ターンプレイヤーでない方も、自分のカードをタップして出したマナで置ける
    （相手のターンに出したマナも、ターンの終わりに消える）
  - `stack` なら、「フィールド上」でないゾーンに置いた、発動する効果を持つカード（呪文）はスタックに積まれ、一番上のものしか
    解決できない。スタックが空でなければ、インスタント以外は置けず、攻撃・ブロック・ターン終了もできない
  - `manaChoice` のあるカードは、タップするたびにその中から色を1つ選んでマナを出す
  - 飛行を持つカードの攻撃は、飛行か到達を持つカードでしかブロックできない
  - 発動して解決するときに、対象を選ぶ範囲の動きの対象（フィールドのカードの位置）を1つ選ぶ
  - ターンの終わりに、どのカードのダメージとターンの終わりまでの変化も消える。新しいターンプレイヤーが引く枚数より少ないデッキしかなければ、そのプレイヤーの負け
  - ライフのルール（`life` が 1 以上）でどちらかのライフが 0 になったときと、デッキ切れのときは、対戦が終わる（それ以上動けない）

ターンのあるモデルの盤面は、どれもターンのないモデルで到達できる盤面である（`TReachable.reachable`）。そのため、
ターンのないモデルで証明した★・盤面の制約・受け入れた証明のジョブは、ターンのある対戦でもそのまま成り立つ
（`TReachable.of_reachable`）。ターンがあるから言える性質（召喚の上限 `TReachable.summons_le`、
1ターンに1枚1回の攻撃 `TReachable.attacked_bagLe`、種類ごとの上限 `TReachable.placed_le`、
タップとブロックの記録がいつもフィールドのカードの一部であること `TReachable.fits`、
1ターンに払うマナはそのターンにタップで出したマナを超えないこと `TReachable.spent_le`）はターンのあるモデルで証明する。
マナとタップはターンのあるモデルだけにあり、ターンのないモデルはコストを無視して置ける（より自由なモデルなので、
そこで証明した性質はマナのある対戦でも成り立つ）。
Unity のテストプレイは、C# に移したターンのあるモデル（`Match`、差分テスト済み）で動く。

## Selector（範囲の指定）

フィールド上のカードのうち、すべての条件に合うものを選ぶ。意味は `Selector.matches` が定める。

| フィールド | 型 | 意味 |
|---|---|---|
| `types` | 文字列の配列 | カードの種類（このどれか） |
| `tags` | 文字列の配列 | このすべてを持つ（空なら条件なし） |
| `side` | `"self"` / `"opp"` / `"both"` | 効果の持ち主から見た陣営 |
| `faceUpOnly` | 真偽 | 表側表示のカードだけ |
| `excludeSelf` | 真偽 | このカード自身を除く |
| `near` | `"any"` / `"adjacent"` / `"sameColumn"` | 効果を持つカードのマスとの関係（条件なし・隣のマス・同じ縦列） |
| `target` | 真偽 | 対象を1つ選ぶ。解決するときに、範囲に合うカードを1枚選び、そのカードだけに行う（選ばなければ何も起きない）。発動の動きの範囲だけに使え、永続効果（無効・攻撃力の変化・守備力の変化）の範囲には使えない |

マスの関係は、効果を持つカードのマスから見る。発動した魔法・罠は、解決する前に置かれていたマスから見る。
効果を持つカードと範囲のカードのどちらかがマス目の上にないときは、関係は成り立たない。
無効の範囲（`negate`）には、まだマスの関係を使えない（無効の判定の総当たりがマスを考えないため）。

## 形式の検査（`Game.check`）

読み込んだあと、次を調べて問題を日本語ですべて返す。空なら `WellFormed`。

- カードの種類が空でない・重複しない
- 初期手札がデッキの枚数以下
- ゾーン名が重複しない。マスの数が1以上。置けるカードの種類が空でなく、ルールにある
- デッキ・墓地の役割のゾーンがちょうど1つずつあり、マス1つ・何枚でも・すべての種類を置ける・「フィールド上」に数えない・マスの位置を付けない
- マスの位置があるゾーンは、位置の数がマスの数と同じで、どの位置も盤面の中。相手の側も含めて、マスどうしが重ならない
- 無効の範囲にマスの関係を使わない
- カード名が重複しない。カードの種類と範囲の指定の種類がルールにある。範囲の種類が空でない
- 発動する効果に動きが1つ以上ある。ドローの枚数・ダメージ・回復する量が1以上
- 戦闘できる種類がカードの種類にある。戦闘できる種類があれば初期ライフが1以上
- 攻撃力の変化・守備力の変化・カードへのダメージ・ターンの終わりまでの変化が0でなく、その範囲に戦闘できる種類がある
- 永続効果の範囲で対象を選ばない。打ち消す範囲の種類を「フィールド上」でないゾーンに置ける
- コストの色・出るマナの色・選べるマナの色がマナの色にある。選べるマナの色が重複せず、マナの色と両方は持たない。
  マナの色や選べる色があれば、出るマナの量が1以上
- いつでも置ける種類がカードの種類にある

盤面の制約や★の定理は、形式の検査が通ることを前提にしない（形式に誤りがあっても成り立つ）。形式の検査は「書いても意味がない」
ものを入口で止めるためのもので、そのうち対戦の意味に関わる警告は、意味を `CardGen/Warnings.lean` で証明している。例えば：

| 警告 | 証明していること |
| --- | --- |
| 範囲のカードの種類が空 | どのカードにも当たらない（`Selector.matches_eq_false_of_types_nil`） |
| 範囲の種類・タグがルールにない | ルールにある種類・タグのカードには当たらない（`Selector.matches_known_types`・`Selector.matches_eq_false_of_unknown_tag`） |
| ドロー・ダメージ・回復が0 | 盤面を変えない（`State.applyAction_draw_zero` など） |
| カードへのダメージ・ターンの終わりまでの変化が0、範囲に戦闘できる種類がない | 状態の確認と同じで、ダメージや変化を与えない（`State.strike_eq_sweep`・`State.pumpAll_eq_sweep`） |
| 打ち消す範囲の種類を「フィールド上」でないゾーンに置けない | 到達できる盤面で何もしない（`State.counter_eq_self`） |
| 攻撃力・守備力の変化が0、範囲に戦闘できる種類がない、永続効果で対象を選ぶ | その効果が加える量は0（`modTerm_boost_zero` など） |
| 無効の範囲で対象やマスの関係を使う | 無効の関係で何にも当たらない（`Selector.matches_negView_target`・`Selector.matches_negView_near`） |
| 発動する効果に動きがない | 無効にされて解決したのと同じ（`State.resolve_nil`） |
| カードの種類がルールにない、ゾーンのマスの数が0・置ける種類が空 | そのカードはフィールドに出ない、そのゾーンにはカードがない（`Reachable.type_known`・`Reachable.zone_used`） |
| マナの色があるのに出るマナの量が0 | タップしてもマナは出ない（`manaOut_eq_nil`） |
| 置ける枚数の上限が0 | その種類は1枚も置けない（`TReachable.placed_none`） |
| 初期手札がデッキの枚数より多い／戦闘できる種類があるのに初期ライフが0 | 初期手札はデッキの枚数までしか引けない（`start_hand_length`）／ライフで対戦は終わらない（`Match.over_life_zero`） |

残り（重複・版・デッキと墓地の役割のゾーンの決まりなど）は、中間表現の書き方の決まりである。
C# の `Check.Game` は、手で作った例と、乱数で見本をあちこち壊した 300 件で、Lean の `Game.check` と同じ文を同じ順に返すことを確かめている。

## 表せないもの（プロトタイプの範囲外）

ルールの数値を変える効果、カードの種類を変える効果（「〜扱い」）、攻撃力を「〜にする」効果、
表示形式（攻撃表示・守備表示。表側表示は攻撃、裏側表示は守備として扱う）、フェイズ、
召喚の条件、発動のタイミング（インスタントの種類を除く）、デッキの構成、無効の範囲のマスの関係、カードを別のマスへ動かす効果。
MTG に近づけるうえでは、プレイヤーを対象に選ぶこと、対象を唱えるときに選ぶこと（ここでは解決するときに選ぶ）、
飛行・到達・トランプル以外の能力も表せない（優先権は公理として入れた。「ターン」の節）。

ターンの記録（攻撃した・タップした・ブロックした など）は、カード・ゾーン・マス・表裏が同じカードを区別しない。
「何枚でも」のゾーンに同じカードが2枚以上あると、どちらが記録のカードかは決まらない（記録の枚数だけが意味を持つ）。
MTG 風の見本は、そうならないように戦場を「1枚まで」のマス目にしている。

2人で共有するマス（エクストラモンスターゾーンなど）は、このプロトタイプでは扱わないと決めた。

## 検査ツール

```
lake exe cardgen ファイル.json          # JSON で報告
lake exe cardgen ファイル.json --text   # 人が読む形で報告
lake exe cardgen - < ファイル.json      # 標準入力から読む
```

形式の誤りがあれば終了コード 1。報告（`CardGen/Report.lean`）の中身は次のとおり。

| フィールド | 意味 |
|---|---|
| `ok` | 形式の誤りがないか |
| `errors` | 形式の誤り（日本語） |
| `claims` | ルールから導いた★。`text`・`grounds`（根拠）・`status`・`theorem`（証明した定理） |
| `negation` | 無効の関係の検査。`status`・`message`・`edges`（無効にしうる関係の矢印）・`groups`（循環のまとまりごとの総当たりの結果と、一番悪い盤面）・`theorem` |

`status` は `proved`（証明済み）、`counterexample`（反例あり）、`choice`（プレイヤーの選択）、`unknown`（未確定）のどれか。
