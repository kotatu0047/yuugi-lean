# 中間表現（版 3）

ビジュアルエディタが出力し、Lean の検査ツールと C# のゲームエンジンが共有する JSON 形式。
定義は `CardGen/IR.lean`、見本は `CardGen/sample.json`（`CardGen/Sample.lean` と同じ内容であることをビルドで確認）。

## 前提（全ユーザー共通、中間表現には書かない）

- プレイヤーは自分と相手の2人
- 相手のフィールドは自分のフィールドを逆さまにした形。ゾーンは1人分だけ書く

## 全体

| フィールド | 型 | 意味 |
|---|---|---|
| `version` | 数 | 形式の版。今は `3`（版 2 でライフと戦闘、版 3 でターンのルールを加えた） |
| `rules` | Rules | ゲームのルール |
| `cards` | Card の配列 | カードの定義 |

`Option` でないフィールドはすべて必須（省略すると読み込みエラー）。

## Rules

| フィールド | 型 | 意味 |
|---|---|---|
| `cardTypes` | 文字列の配列 | カードの種類（例：モンスター、魔法、罠） |
| `deckSize` | 数 | 1人あたりのデッキの枚数 |
| `handSize` | 数 | 初期手札の枚数 |
| `zones` | Zone の配列 | ゾーンの定義（1人分） |
| `life` | 数 | 初期ライフ |
| `fighters` | 文字列の配列 | 戦闘できる（攻撃する・攻撃される）カードの種類。空なら戦闘はない |
| `summonsPerTurn` | 数 | 1ターンに置ける、戦闘できる種類のカードの枚数（通常召喚の回数）。0 なら制限なし |
| `drawPerTurn` | 数 | ターンの最初に引く枚数 |
| `firstTurnDraw` | 真偽 | 先攻の最初のターンにも引くか |
| `firstTurnAttack` | 真偽 | 先攻の最初のターンにも攻撃できるか |

Unity のエディタは、版 2 のファイルを開くとターンのルールを既定の値（1・1・引かない・攻撃できない）にして版 3 に上げる。

## Zone

| フィールド | 型 | 意味 |
|---|---|---|
| `name` | 文字列 | ゾーンの名前 |
| `count` | 数 | 1人あたりのマスの数 |
| `capacity` | `"one"` / `"many"` | 1マスに1枚まで／何枚でも |
| `role` | `"deck"` / `"grave"` / `"plain"` | デッキ・墓地として手順が使うゾーンか |
| `onField` | 真偽 | 「フィールド上」に数えるか |
| `admits` | 文字列の配列 | 置けるカードの種類 |

## Card と効果

| フィールド | 型 | 意味 |
|---|---|---|
| `name` | 文字列 | カード名（重複不可） |
| `type` | 文字列 | カードの種類 |
| `tags` | 文字列の配列 | 属性・種族など |
| `effects` | Effect の配列 | 効果 |
| `attack` | 数 | 攻撃力（戦闘できる種類のカードが使う） |
| `defense` | 数 | 守備力（裏側表示で攻撃されたときに使う） |

Effect は次のどれか。

- `{"activated": {"actions": [Action, …]}}`：発動し、解決したときに動きを順に行う
- `{"negate": {"target": Selector}}`：表側表示でフィールド上に存在する限り、範囲に合うカードの効果を無効にする
- `{"boost": {"target": Selector, "amount": n}}`：表側表示でフィールド上に存在し、効果が無効にされていない限り、
  範囲に合うカードの攻撃力を n 変える（n は負でもよい。攻撃力は 0 未満にならない）

Action は次の5種類。どれもカードを移すかライフを変えるだけなので、盤面の制約（★）を崩さないことを証明済み（`CardGen/Inv.lean`）。

- `{"destroy": {"target": Selector}}`：範囲に合うカードをすべて破壊し、持ち主の墓地へ送る
- `{"bounce": {"target": Selector}}`：範囲に合うカードをすべて持ち主の手札に戻す
- `{"draw": {"count": n}}`：発動したプレイヤーがデッキからカードを n 枚引く（足りなければある分だけ。n は1以上）
- `{"damage": {"amount": n}}`：相手に n のダメージを与える（ライフは 0 より下がらない）
- `{"heal": {"amount": n}}`：発動したプレイヤーのライフを n 回復する

## 戦闘

表側表示の戦闘できるカードは、相手のフィールド上の戦闘できるカードを攻撃できる（相手にいなければ直接攻撃）。
攻撃力は、元の攻撃力に、無効にされていない `boost` を足したもの（`State.atkOf`）。

- 表側表示のカードどうし：攻撃力の低い方を破壊し、差をそのコントローラーへのダメージにする。同じなら両方を破壊する（ともに 0 なら何も起きない）
- 裏側表示のカード：守備力で受ける。攻撃力が高ければ破壊し（ダメージなし）、低ければ差を攻撃した側へのダメージにする。裏側のまま残る
- 直接攻撃：攻撃力をそのまま相手へのダメージにする

## ターン（`CardGen/Turn.lean`）

対戦のモデルは2段になっている。

- **ターンのないモデル**（`Step`・`Reachable`）：どちらのプレイヤーもいつでも何度でも、置く・発動する・攻撃する・引くことができる。
  ★と盤面の制約は、このモデルのすべての盤面について証明する
- **ターンのあるモデル**（`Match.step?`・`TReachable`）：その上にターンを重ねたもの
  - カードを置く・攻撃するのはターンプレイヤーだけ。場のカードの発動はどちらのプレイヤーもいつでもできる
  - 戦闘できる種類のカードを置くのは、1ターンに `summonsPerTurn` 枚まで
  - 攻撃は1ターンに1枚1回まで。先攻の最初のターンは `firstTurnAttack` のときだけ攻撃できる
  - 「ターン終了」で相手のターンになり、新しいターンプレイヤーが `drawPerTurn` 枚引く（デッキが足りなければある分だけ）。
    先攻の最初のターンは `firstTurnDraw` のときだけ引く。それ以外に引くのは効果によるときだけ

ターンのあるモデルの盤面は、どれもターンのないモデルで到達できる盤面である（`TReachable.reachable`）。そのため、
ターンのないモデルで証明した★・盤面の制約・受け入れた証明のジョブは、ターンのある対戦でもそのまま成り立つ
（`TReachable.of_reachable`）。ターンがあるから言える性質（召喚の上限 `TReachable.summons_le`、
1ターンに1枚1回の攻撃 `TReachable.attacked_bagLe`）はターンのあるモデルで証明する。
Unity のテストプレイは、C# に移したターンのあるモデル（`Match`、差分テスト済み）で動く。

## Selector（範囲の指定）

フィールド上のカードのうち、すべての条件に合うものを選ぶ。意味は `Selector.matches` が定める。

| フィールド | 型 | 意味 |
|---|---|---|
| `types` | 文字列の配列 | カードの種類（このどれか） |
| `tags` | 文字列の配列 | このすべてを持つ（空なら条件なし） |
| `side` | `"self"` / `"opp"` / `"both"` | 効果の持ち主から見た陣営 |
| `faceUpOnly` | 真偽 | 表側表示のカードだけ |
| `excludeSelf` | 真偽 | このカード自身を除く |

## 形式の検査（`Game.check`）

読み込んだあと、次を調べて問題を日本語ですべて返す。空なら `WellFormed`。

- カードの種類が空でない・重複しない
- 初期手札がデッキの枚数以下
- ゾーン名が重複しない。マスの数が1以上。置けるカードの種類が空でなく、ルールにある
- デッキ・墓地の役割のゾーンがちょうど1つずつあり、マス1つ・何枚でも・すべての種類を置ける・「フィールド上」に数えない
- カード名が重複しない。カードの種類と範囲の指定の種類がルールにある。範囲の種類が空でない
- 発動する効果に動きが1つ以上ある。ドローの枚数・ダメージ・回復する量が1以上
- 戦闘できる種類がカードの種類にある。戦闘できる種類があれば初期ライフが1以上
- 攻撃力の変化が0でなく、その範囲に戦闘できる種類がある

## 表せないもの（プロトタイプの範囲外）

ルールの数値を変える効果、カードの種類を変える効果（「〜扱い」）、攻撃力を「〜にする」効果、
表示形式（攻撃表示・守備表示。表側表示は攻撃、裏側表示は守備として扱う）、フェイズ、デッキ切れの敗北、
召喚の条件、発動のタイミング、デッキの構成、フィールドのマスの幾何学的な並び。

## 検査ツール

```
lake exe cardgen ファイル.json          # JSON で報告
lake exe cardgen ファイル.json --text   # 人が読む形で報告
lake exe cardgen - < ファイル.json      # 標準入力から読む
```

形式の誤りがあれば終了コード 1。報告（`CardGen/Report.lean`）の中身は次のとおり。

| フィールド | 意味 |
|---|---|
| `ok` | 形式の誤りがないか |
| `errors` | 形式の誤り（日本語） |
| `claims` | ルールから導いた★。`text`・`grounds`（根拠）・`status`・`theorem`（証明した定理） |
| `negation` | 無効の関係の検査。`status`・`message`・`edges`（無効にしうる関係の矢印）・`groups`（循環のまとまりごとの総当たりの結果と、一番悪い盤面）・`theorem` |

`status` は `proved`（証明済み）、`counterexample`（反例あり）、`choice`（プレイヤーの選択）、`unknown`（未確定）のどれか。
